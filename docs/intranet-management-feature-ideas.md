# Intranet management feature ideas

This is a backlog of extensions to things the intranet already owns. It avoids
generic "employee engagement" features and avoids creating a second source of
truth next to Clockodo, Convex, OneDrive, or the existing
specialist modules.

## Best first additions

These are visible improvements with a contained first version. They should be
implemented as dashboard cards, dialogs, or focused pages, not a new framework.

## Higher-leverage platform improvements

These make several current modules better at once, but should still be shipped
in small slices.

| Feature                                        | Why it is worth it                                                                                                                                             | Reuses                                                                                       | Sensible first slice                                                                                                                                               |
| ---------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **Universal "create" launcher**                | The dashboard already has several quick actions, while each module uses a dialog or dedicated page. A single launcher makes frequent actions discoverable.     | Command palette, page-header actions, existing dialogs/routes.                               | Add only the current common actions: event, announcement, IT ticket, suggestion, applicant, and upload. Respect capabilities and open the module’s existing UI.    |
| **Saved views for dense lists**                | Managers repeatedly recreate the same directory, ticket, applicant, and error filters.                                                                         | Current client filters, `userPreferences`.                                                   | Persist named filters per module and user. Start with directory and IT tickets; do not make a generic query-builder.                                               |
| **“Follow” rather than blanket notifications** | People could opt into meaningful updates for a guidebook, applicant, suggestion, error measure, or project without receiving every global change.              | Notifications, current user preferences, record ownership.                                   | Implement follows for guidebooks and error measures first, with one notification type per important event.                                                         |
| **Cross-module related links**                 | A useful record often has context elsewhere: a guidebook for an IT category, an update about a resolved error, or a calendar event for an applicant interview. | Existing deep-link patterns, attachments, rich links.                                        | Add a small, typed “related links” section to two high-value records (IT tickets and error measures) before considering a shared relation table.                   |
| **Mobile quick review mode**                   | Managers often need to approve, acknowledge, or check a queue on a phone; their current rich desktop pages should not be squeezed into cards.                  | Bottom navigation, mobile dialogs/sheets, RouteTabs pattern, notifications.                  | A “Review” page that surfaces existing pending approvals and open measures as large tap targets, then deep-links to their owning flows.                            |
| **Delegated absence/approval cover**           | Covers holidays without giving a replacement permanent admin rights.                                                                                           | Manager relationships, role/capability model, Clockodo approval workflows, audit log.        | Time-box a specific delegation with a start/end date, explicit scopes, visible banner, and audit entries. This needs careful server-side enforcement from day one. |
| **Management activity digest**                 | A calm, once-daily internal digest keeps managers aware of unattended work without training people to stare at dashboards.                                     | Notifications, updates email infrastructure, admin overview, ticket/measure/suggestion data. | In-app digest first: counters and deep links. Make email opt-in later, with quiet hours and no activity surveillance data.                                         |

## Things to deliberately handle carefully

- **No employee activity tracking.** ActivityTrack was removed on purpose
  (2026-10-05). Don't reintroduce device, phone or time-tracking state as a
  presence signal, leaderboard, ranking or disciplinary input.

- **Keep absence privacy intact.** The current calendar intentionally exposes
  other people’s vacation but not sick/personal/other absence details. New
  availability planning must preserve that boundary.

- **Keep capability checks on the server.** Frontend visibility is helpful,
  but approval delegation, offboarding, people data, files, and applicant
  work need the same `require*`/capability enforcement as their underlying
  actions.

- **Avoid a generic task platform for now.** The product already has tickets,
  corrective measures, suggestions, approval queues, applicant next steps,
  and sales topics. The useful first move is a unified view and linking—not
  migrating every system into a new, vague “tasks” abstraction.

## Recommended delivery order

1. Manager morning brief, notification grouping, and ticket request timeline.
2. Approval inbox, guidebook freshness, and suggestion decision notes.
3. Profile completeness and new-starter checklist.
4. Corrective-action ownership, calendar conflict hints, and applicant
   pipeline health.
5. Universal create launcher and saved views after the high-traffic workflows
   prove which actions and filters deserve to be shared.
